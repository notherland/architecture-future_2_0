# Задание 1. Проблемные места и приоритизация

## Ключевые бизнес-сценарии
1. Быстрая подготовка управленческой и операционной отчётности (self-service витрина).
2. Независимое развитие финтех-направления (кредиты, счета, платежи).
3. Независимое развитие ИИ-сервисов для медицины (без попадания медкарт в витрину).
4. Масштабирование и подключение новых бизнесов (фарма, электроника).
5. Соблюдение ИБ и требований регуляторов (медицина + финансы).

---

## Проблемные места

| # | Проблема | Страдающие бизнес-сценарии | Влияние на бизнес |
|---|----------|----------------------------|-------------------|
| P1 | Вся бизнес-логика и данные в монолитном DWH (SQL Server 2008) | 1–4 | Долгий time-to-market; любое изменение трогает общее хранилище |
| P2 | Отчёты строятся часами из-за объёма (сотни ТБ) и множества трансформаций | 1 | Задержки управленческих решений; низкая скорость реакции |
| P3 | Power BI с кастомизациями поверх DWH, нет self-service портала | 1, 4 | Аналитика зависит от IT; домены не масштабируются независимо |
| P4 | PowerBuilder + устаревший DWH как операционный фронт | 2, 3 | Риски отказов, сложно развивать продукты клиники/смежных сервисов |
| P5 | ESB на Apache Camel — единая точка интеграции | 2, 3, 4 | Узкое место при подключении новых направлений |
| P6 | Медданные и финданные в одном контуре без чётких границ доменов | 3, 5 | Риск нарушения регуляторики; нельзя безопасно открыть витрину |
| P7 | On-prem / устаревшее железо, нет гибкого масштабирования | 1, 4 | Высокая стоимость поддержки; медленный запуск новых доменов |

---

## Приоритизация (MoSCoW + матрица Эйзенхауэра)

### MoSCoW

| Приоритет | Проблемы | Связь с целями бизнеса |
|-----------|----------|------------------------|
| **Must** | P1, P2, P6 | Без разделения доменов и ускорения отчётности недостижимы цели «через год»; без границ данных — риск для лицензии/регуляторов |
| **Should** | P3, P5 | Нужны для портала самообслуживания и подключения партнёров без роста связности |
| **Could** | P7 (полный уход с on-prem) | Важно для затрат и масштаба, но допустим поэтапный переезд |
| **Won't (сейчас)** | Полный отказ от PowerBuilder во всех доменах | Допускается временное легаси в отдельных доменах |

### Матрица Эйзенхауэра

|  | Срочно | Не срочно |
|--|--------|-----------|
| **Важно** | P2 (отчёты часами), P6 (регуляторика) | P1 (декомпозиция DWH), P3 (витрина), P5 (замена ESB) |
| **Не важно** | P4 точечные инциденты PowerBuilder | Косметические улучшения BI без смены архитектуры |

### Итоговый порядок работ
1. **P6 + границы доменов** — критично для выручки финтеха и качества медсервисов (комплаенс).
2. **P1 + P2** — критично для скорости решений и TTM витрины.
3. **P3 + P5** — критично для масштабирования новых бизнесов.
4. **P7 + частичный P4** — снижение затрат и рисков, поэтапно.
