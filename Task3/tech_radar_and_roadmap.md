## Роадмап (привязка к бизнес-целям)

### Этап 0 (0–2 мес.) — Архитектура и границы
- **Шаги**: согласовать целевую архитектуру; зафиксировать домены; каталог запрещённых для витрины данных (медкарты, исследования).
- **Результат**: согласованное решение; backlog витрины по доменам.
- **Ответственные**: архитекторы + владельцы доменов.
- **Ресурсы**: 2–3 архитектора, workshop с бизнесом.
- **Зачем бизнесу**: база для TTM и комплаенса; цель «промежуточное состояние».

### Этап 1 (2–5 мес.) — Платформа и облако
- **Шаги**: облачный foundation (сеть, IAM, Terraform); Event Bus; пилот CDC из DWH; каркас Lakehouse.
- **Результат**: среды доменов; события вместо точечных правок DWH.
- **Ответственные**: Platform team.
- **Ресурсы**: cloud budget, 4–6 инженеров платформы.
- **Зачем**: масштабирование, снижение затрат на железо, надёжность.

### Этап 2 (4–8 мес.) — Независимость Fintech и Clinic/AI
- **Шаги**: вынести финлогику из DWH в Fintech OLTP; закрытый контур Clinic↔AI; MDM клиента.
- **Результат**: релизы финтеха/ИИ без деплоя DWH.
- **Ответственные**: Fintech, Clinic, AI teams.
- **Ресурсы**: продуктовые команды доменов + безопасность.
- **Зачем**: скорость продуктов, качество сервисов, лицензионные требования.

### Этап 3 (6–10 мес.) — Портал самообслуживания
- **Шаги**: витрины KPI (без медкарт); semantic layer; портал + RBAC; пилот отчётов HQ.
- **Результат**: сотрудник строит отчёт по доступу самостоятельно.
- **Ответственные**: Analytics + Platform.
- **Ресурсы**: data engineers, BI, UX.
- **Зачем**: решения за минуты, а не часы; цель «финальное состояние».

### Этап 4 (9–12 мес.) — Партнёры и вывод легаси
- **Шаги**: коннекторы Pharma/Devices; перевод критичных отчётов с DWH; PowerBuilder только где временно нужно.
- **Результат**: новые бизнесы подключаются через Bus; DWH на hold/выводе.
- **Ответственные**: Platform + Partners + домены.
- **Ресурсы**: интеграторы, data stewards.
- **Зачем**: рост экосистемы, меньше затрат на легаси.
